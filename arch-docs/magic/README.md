# Zenderal magic dataset

**Every magic record in the installed Zenderal modlist, with its load-order-WINNING values — the
numbers actually in effect in game.** Built for rebalancing: when Enderal defines a spell, EGO
overrides it and a third mod overrides that, [`data/spells.json`](data/) holds the version the
engine uses, plus the full override chain and what each winner changed.

Generated by [`tools/MagicExtract`](tools/MagicExtract/) (C#, Mutagen). Regenerate with:

```powershell
powershell -File arch-docs/magic/tools/Run-MagicExtract.ps1     # paths come from .claude/config/tools.json
python arch-docs/magic/tools/verify_against_yaml.py             # optional cross-check vs reference/
```

## What's here

| File | Contents |
|---|---|
| [`magic-overview.md`](magic-overview.md) | GENERATED — counts, conflict winners, schools, cost model |
| [`magic-conflicts.md`](magic-conflicts.md) | GENERATED — every multi-source record, per-field before → after |
| `data/spells.json` … `data/game-settings.json` | The datasets: SPEL, MGEF, ENCH, SCRL, ALCH, SHOU, LVSP, GMST |
| `data/spells.csv` | Flat balance sheet for spreadsheet work — **player-obtainable spells only** (a winning Book must teach it; NPC/trap/voice variants and script-granted spells are excluded), grouped by school then type. The complete spell set is in `spells.json`, where each teachable spell carries `taughtBy` |
| `data/scrolls.csv` | Flat balance sheet of all winning scrolls (cost, value, weight), sorted by name |
| `data/enchantments.csv` | Flat balance sheet of all winning enchantments, grouped by enchant type |

All three CSVs carry an **Arcane Fever** column: the base no-perk fever one cast/use inflicts, read
off the record's own `_00E_IncreaseArcaneFever*` / `_00E_WohltatArkanistenfieber` effect items. EGO
ships perk-gated HIDDEN variants of these at reduced magnitude, mutually exclusive by `HasPerk`
conditions, so the column takes the MAX fever-effect magnitude, never the sum. Empty = no fever.
| `data/lookups.json` | School names, cost-model GMST curve, PERK/KYWD/PROJ/EQUP name tables |
| `data/load-order.json` | Per-plugin: enabled, header version, BEES dependency, exclusion reason |
| `data/manifest.json` | Run metadata, counts, warnings |
| `data/.provenance.json` | GITIGNORED — full per-plugin DTO snapshot of every override chain |

## Reading a record

Records are addressed by `formKey` and field names match Mutagen/Spriggit/xEdit vocabulary. The
`provenance` block is the point of the dataset:

```jsonc
"provenance": {
  "definedIn": "Skyrim.esm",              // remember: Skyrim.esm IS base Enderal
  "winner": "Enderal SE - Gameplay Overhaul.esp",
  "chain": ["Skyrim.esm", "Enderal SE - Gameplay Overhaul.esp"],
  "changedFields": ["editorId", "cost", "halfCostPerk", "effects"],
  "winnerNeedsBees": false                // true = this value only applies because BEES is installed
}
```

`cost.computedAutoCost` is the CK auto-cost recomputed from the **winning** magic effects:

```
effectCost    = floor( mgef.BaseCost * max(magnitude,1)^1.1 * durFactor^1.1 )
durFactor     = 1 for Concentration effects (charged per second), else (duration==0 ? 10 : duration)/10
spellAutoCost = Σ effectCost      // per-effect floor, then sum
```

`costDrift ≠ 0` on a non-`ManualCostCalc` spell means its stored cost no longer matches its live
effect data — usually an override edited a shared MGEF (or the spell's durations) without a CK
recompute. **223 spells in the current list carry real drift**; they are prime rebalancing targets.
Base Enderal itself ships four such records (BoundSword, FlamesRightHand, Flames3,
FlameCloakLeftHand), which is why the formula gate sits at 97% rather than 99%.

## Trust, verification, limits

Every run self-checks, in order: the **strings canary** (the four renamed school names must resolve —
proves delocalization AND that we read Enderal's `Skyrim.esm`, not vanilla's), the **BEES canary**
(see below), **cost-formula validation** on base Enderal's self-consistent spells, a **raw GRUP
scan** (a second, Mutagen-free binary parser must find the same unique FormKeys per group), and
**12 golden fixtures** in [`tools/MagicExtract/golden.json`](tools/MagicExtract/golden.json).
`tools/verify_against_yaml.py` additionally cross-checks against the Spriggit 0.40 trees in
`reference/` — two independent decoders of the same bytes; last full run: 4,157 records, zero
disagreements.

**BEES dependency.** 67 enabled plugins are HEDR 1.71 and load *only* because
*Backported Extended ESL Support* is installed (see CLAUDE.md's form-version-ceiling section).
The extractor hard-fails if those plugins are present without BEES, and every record whose winner
is one of them carries `winnerNeedsBees: true`.

**What a record dump cannot see:** Papyrus. Much of Enderal's magic balance lives in scripts
(`_00E_A1_ArcticWindME` → `_00E_A1_ArcticWindSC` with a `PlayerLevel` property). MGEFs with
attached scripts carry a `scripts[]` block — treat those as *flagged for manual reading* in
`reference/base/EnderalScripts/source/scripts/`. Runtime spell cost past `baseCost`
(skill curve, perks, dual-cast) is likewise approximate — see `costModel` in `data/lookups.json`.

## Guardrails

- **MagicExtract is READ-ONLY and must stay that way.** It uses Mutagen 0.54.4, which is *newer*
  than the Mutagen inside the repo's pinned Spriggit 0.40.0. That is safe only because it never
  writes a plugin. Authoring still goes exclusively through Spriggit 0.40.0 (CLAUDE.md).
- The NuGet version is pinned as `[0.54.4]` with a committed `packages.lock.json` — NuGet's index
  lists ancient `7.1.0`/`23.4.0` packages *after* 0.54.4; a floating restore could pick one.
- The dataset reflects **profile `Zenderal Alpha 0.3` at extraction time**. Re-run after any
  modlist change; the JSON is deterministically ordered so `git diff` shows exactly what moved.

## Write-back (phase 2, not built)

The schema is designed so a later generator can diff an edited copy of these files against the
extracted ones and emit Spriggit override YAML — forwarding the winning values of every field you
did **not** change (guardrail 5). Nothing does this yet; edits to `data/` do nothing on their own.
