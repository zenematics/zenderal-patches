## What it does

**Ice Elementals floated up into the air when hit** (reported 2026-10-12). Confirmed in game to be **Precision's live hit impulse** (MCM *Apply impulse on hit* off = no float; `sae staggerStart` alone = no float); the curator wants the impulse kept for everything else. Precision 2.0.x (ersh1/Precision, GPL-3.0) gives LIVING actors an active ragdoll and, while it is active, turns gravity off for it (`bDisableGravityForActiveRagdolls`, hard-coded) and has no per-actor impulse setting (`ToggleDisableActor` removes the actor from its collision world; the API's `PreHitModifier` is Damage/Stagger only). **Attempt 1 failed:** an SKSE plugin on Precision's API (`PostHitCallback` + `PrePhysicsStepCallback`, vendored `PrecisionAPI.h`) clamping the ragdoll root's upward velocity changed nothing visible. Its debug timeline (kept as `debugLog` / observe-only `clamp: false`) showed why: the actor's own Z never moves, and the WHOLE ragdoll (COM, thighs, calves, upper arms) jumps +15–25 units within one physics step with no upward velocity and stays there however hard the root is driven down — a constant pose↔ragdoll offset, not an impulse and not ground contact (no body near z 0). **Cause:** the frost atronach is the only skeleton whose limb bodies are `bhkRigidBodyT` (8, box shapes, local offsets from their bone); every other skeleton uses plain `bhkRigidBody` storing the bone's bind transform (translation × skeleton scale × 69.99 = node world, rotation = node world rotation — verified on every flame-atronach body and on the frost atronach's COM; its skeleton scale is 1.3). adamhynek's PLANCK (VR-only, Nexus 66025) added rigidBodyT handling to its pose↔ragdoll mapping "mainly relates to frost atronach" (adamhynek/activeragdoll `61bce7e538`); Precision's source never mentions rigidBodyT. **Attempt 2 (current):** `src/PrecisionLiftFix/tools/01-convert-frost-atronach-skeleton.py` rewrites XPMSSE's skeleton at the binary level: each T body → plain `bhkRigidBody` in the normal convention, its offset moved into a new `bhkConvexTransformShape` (84 bytes, translation in Matrix44 floats 12–14, w 0 — layout copied from SMIM's `milllogpile.nif`), centre of mass and its side of each `bhkRagdollConstraint` pivot shifted by the offset (all offsets have identity rotation, asserted, so inertia/axes are unchanged); asserts 8 converted, 12 pivots moved, read-back conventions. Generated, never committed (XPMSSE's file). Sorts above `Zenderal - Frost Atronach SE Fix` and XPMSSE. **FAILED in game 2026-10-12: no hit registration on the atronach, then a crash** — NSF `Crash_2026_10_12_10-30-56.txt`, `SkyrimSE.exe+AA07E4` in the collision dispatcher, called from `hkbRagdollDriver` by `Precision.dll+5890F`, between the converted `NPC L Thigh` body and a tree's `TrunkBone` list shape. **A `bhkConvexTransformShape` inside a ragdoll body is NOT supported** by the engine/Precision's ragdoll path, though statics use it fine. The MO2 mod was removed from the list the same day (folder moved to `E:/Zenderal-backups/failed-mods/`); nothing of it is deployed. Untested next idea: the same plain-body conversion but replacing each box with a `bhkCapsuleShape` whose endpoints carry the offset — the shape every working skeleton uses, so no wrapper block. (Deprioritised: PLANCK's changelog names a SECOND cause too — frost atronach animations stretch its limbs away from the ragdoll's joint pivots, which PLANCK fixes by re-fitting pivots to the pose — so a skeleton edit addresses at most half.) **Attempt 3 (current, 2026-10-12):** the DLL in `"mode": "disable"` — calls Precision's API `ToggleDisableActor(handle, true)` ("Disables Precision for an actor (removes the ragdoll etc.)") for every loaded actor of a configured race, re-applied every 0.5 s from an SKSE main-thread task (Precision CLEARS its disabled list in `PrecisionHandler::Clear()` whenever the physics world changes) and on any Precision hit on one. No active ragdoll = nothing to float; every other actor keeps the impulse. **Open question:** whether the player's melee still registers on a Precision-disabled actor (it is removed from Precision's collision world; Precision's source does not show a vanilla-hit fallback). Deployed with `debugLog` on, not yet run in game. The real fix if this fails: a GPL fork of Precision porting PLANCK's rigidBodyT pose mapping + pivot re-fit.
