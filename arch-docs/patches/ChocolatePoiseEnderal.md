- **FormID block:** `0x800–0x808`

## What it does

**Chocolate Poise - Reforged was dealing ZERO poise damage list-wide.** `ChocolatePoiseReforged.dll` (v4.0.0) scales every hit against reference items it fetches BY VANILLA EDITORID at startup (`HitEventHandler::InitializeEquipmentCache`): `IronDagger`/`DaedricWarhammer` (weapon min/max), `ArmorHideGauntlets`/`ArmorDaedricGauntlets`, `ArmorHideShield`/`ArmorDaedricShield`, `ArmorDaedricCuirass/Helmet/Boots`. None exist in Enderal, so `ChocolatePoiseReforged.log` shows `[Weapon Cache Min] NULL` … `EffectiveReference=0`, and a debug run (`LogWeaponCalcs`/`LogStaggerCalcs`/`LogMagicEffectCalcs = true`, 2026-10-05) logged `Final Poise Damage: 0.00` on all 65 hits both ways. Fix = 9 NEW unplaced records with exactly those EditorIDs (`po3_Tweaks` editorID cache makes them findable), each a verbatim copy of the Enderal item in the vanilla item's role: `_01E_02_IronDagger` (3), `_04E_31Aeternaschlachthammer` (42), `_01E_05_LeatherArmProtectors`, Skybreaker gauntlets/cuirass/helmet/boots, `_01E_05_LeatherShield`, `_04E_30Wegeslosenschild`; live (EGO-winning) stats. Generated by `src/ChocolatePoiseEnderal/tools/01-build-reference-items.py`. **Plus a CRASH FIX, required the moment poise works:** `PoiseAV::RetrieveFullBodyStaggerFaction` does `LookupByID(0x10CED7)` (vanilla `ForceFullBodyStagger`, absent from Enderal; the old `ChocolatePoise - Enderal.esp` recreated it at its own `0x800`, which Reforged never reads), logs `Failed to find ForceFullBodyStagger faction`, and every poise break then runs `a_target->AddToFaction(ForceFullBodyStagger, 0)` with no null check (`src/PoiseAV.cpp:442`, BlessingS91/Chocolate-Poise-Reforged). The null faction entry crashes the next reaction lookup on that actor: `SkyrimSE.exe+19E6A0` `TESReactionForm::unk_19E690+10`, consistently on poise break once the reference items made breaks possible. Two failed attempts first: an injected FACT at `10CED7:Skyrim.esm` (ESL, then full plugin) was ignored, because **in Enderal `10CED7` is a placed REFR in cell `QKerker`** — CPR's lookup returns it and its faction-type check discards it. No plugin can fix that ID. **Fixed at runtime instead** by the NetScriptFramework plugin `ZenCPRFactionFix.dll` (`src/ChocolatePoiseEnderal/NetScriptPlugin/`, committed `compiled/` DLL shipped to `NetScriptFramework/Plugins`): on main menu it verifies CPR's code bytes at RVA `0x5B542` (`B9 D7 CE 10 00` = `mov ecx, 0x10CED7`), then writes the `ChocolatePoise - Enderal.esp` `0x800` `ForceFullBodyStagger` faction into the `PoiseAV` singleton's field at RVA `0x139108` (singleton `0x139100`, field `+8`) if it is null. That faction is also what the Enderal patch's `PlayerStaggerRoot 0F9926` idle conditions on, so player full-body stagger works too. **Tied to this exact CPR build** — the byte check makes a CPR update a logged no-op, not a crash; re-derive both RVAs (disassemble `RetrieveFullBodyStaggerFaction` and the `PoiseAV` getter) after any CPR update. Log: `overwrite/NetScriptFramework/ZenCPRFactionFix.log`. The plugin itself is back to ESL (only the 9 items). Masters: Skyrim + FS + EGO. **Verified in game 2026-10-05**: reference cache populated (`EffectiveReference=1181.7`), poise breaks occur, no crash with the NSF fix (log: `Patched: ForceFullBodyStagger -> ChocolatePoise - Enderal.esp (form FE0B2800)`) — verify by re-enabling the `Zenderal - DEBUG Chocolate Poise Logging` MO2 mod: the cache lines must name items and `Final Poise Damage` must be non-zero. Generalises: **any SKSE plugin that looks up vanilla EditorIDs is silently dead in Enderal** — grep a DLL's strings for vanilla EditorIDs when one does nothing. **Also ships `SKSE/Plugins/ChocolatePoise.json`** (added 2026-10-08, generated by `tools/02-build-poise-json.py`): the author's file verbatim + `VatyrRace` 2.5, `VatyrRaceLarge` 3.0, `VatyrRaceGiant` 3.5, so Vatyr resist stagger while EGO's damage/power-attack nerf stays. CPR's pool = `BaseHealth` 100 × the race's JSON weight, keyed by race EditorID — **an unlisted race falls back to its `BaseMass` AV, NOT `DefaultRace`** (`PoiseAV::GetBaseActorValue`), and EGO gives all three Vatyr races 1.5. The weight sets only the pool; break health damage (`ApplyCreatureStaggerDamage`) still reads real `BaseMass`. CPR reads that one path only (no user-override file), so the mod must sort above `Chocolate Poise - Reforged`; re-run 02 after any CPR update. Scale: an early sword hit ≈27 poise (`MinPoise` 25), power ×2, mid-attack ×1.5. Deployed, not yet verified in game.

crash came back: `crash-2026-10-20-19-24-09.log`, `SkyrimSE.exe+06C8FAD mov ebx,[rcx+0x58]` (rcx = 0) in
the AI/faction-reaction path, with two Pit Rats and three factions in the relevant objects, right after

plugin, `src/ChocolatePoiseEnderal/SKSEPlugin/` (CommonLibSSE-NG, SE + AE incl. 1.7.104, Address Library
v5; `compiled/ZenCPRFactionFix.dll` committed), shipped to `SKSE/Plugins`. Same logic and same offsets: the
installed CPR (TimeDateStamp `0x6AB9B4F8`, MD5 `729b2b0e…f31`) still has `mov ecx, 0x10CED7` at RVA
`0x5B542`, its PoiseAV getter (RVA `0x8710`) returns the static at RVA `0x139100`, field `+8`. Patches on
main-menu open (after CPR's data-loaded lookup), re-checks on new game / load, writes only a null field.
Log: `My Games\Skyrim Special Edition\SKSE\ZenCPRFactionFix.log` — expect `Patched: ForceFullBodyStagger ->
ChocolatePoise - Enderal.esp`. The NSF DLL was moved to `E:/Zenderal-backups/2026-10-20-cpr-faction-fix-nsf`.
