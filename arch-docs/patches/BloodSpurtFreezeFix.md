## What it does

It stops a hard freeze that hit Fog Wood arena fights three times. The cause is Enhanced Blood Textures' blood
spurts, which aim their impact with the direction (0, 0, 0). The fix comments out those 12 calls and changes
nothing else.

## Cause [verified from the dump, 2026-11-14]

The game froze for good mid-fight, with no crash log:

- 2026-11-06, vatyr waves;
- 2026-11-14 21:36, wolf and werewolf waves, with Argent Verdict's Smite;
- 2026-11-14 22:57, wolf and werewolf waves, with pistol + Midnight Sting.

Shatterveil's watchdog dumped the 21:36 freeze to `C:\Users\frien\AppData\Local\Shatterveil\hang-20261114-213654.dmp`.
22:57 left no dump: Shatterveil only writes one when the game is still in the foreground at 10 s.

**The stuck thread.** In the dump, a job thread sits in `SkyrimSE.exe+B47666` (ID 60796+0x556), the engine's
ray-grid walk: `inc edx; cvtdq2ps; comiss xmm7, xmm0; jae` back. Its counter `edx` was at 0x0C918DD5. The real call
chain, from return addresses that follow a `call` in the exe, runs:

`56624 → 56208 (the ObjectReference.PlayImpactEffect native) → 36215 (BGSImpactManager::PlayImpactEffect) → … → 60832 → 60795 → 60796`

**The arguments.** 56208's own stacked arguments sit at return address + 0x28 … + 0x58: node string pointer,
x = 0, y = 0, **z = 0**, length **512**, apply node rotation **false**, use node local rotation **true**.

**Who passes them.** Scanning every enabled loose script for `PlayImpactEffect` (the pex string table, then the
call arguments from each mod's shipped source):

| Script (mod) | Direction, length, bools |
|---|---|
| `zbloodnpc` (*DF - Enhanced Blood Textures Patch*, wins) | **12 spurts: (0, 0, 0), 512, false, true** (`BloodSpurtLarge`/`Normal`/`Arrow`/`Wolf`); its 42 other calls aim (x, y, −1) |
| `fec_deatheffect*` (Frozen Electrocuted Combustion) | (0, 0, −1), 512 or 128, **true, true** |
| `FL_VFXScript` (Deflection) | (0, 0, 0), length **1**, false, true |
| `zbloodnpcbleed`, `zbloodnpccreatures` (EBT) | aim down |

Only EBT's spurts match. They run:

- on a corpse that is still moving after death (`BloodPooling`, every tick while its position changes);
- after a kill move and on decapitated targets, at the end of `killMoveEffects`;
- on a kill-move hit by a wolf, werewolf, animal, giant or dragon (`BloodSpurtWolf`).

The arena makes plenty of all three.

**Why a zero direction can loop.** In 36215, a direction shorter than its epsilon is set to zero, so the pick ray is
start → start. The ray's start in the dump is an ordinary Fog Wood position (about 1406, −2, 58), so the node is fine.
The end point handed to the grid walk was **(1.4e25, 1.4e25, start z)**: grid coordinates (1.08e23, 1.08e23, 16), with
x and y exactly equal. `while (end >= (float)cell) cell++` cannot reach that, and for anything above 2^31 `edx`
wraps first.

Something between the pick and the walk turns the zero-length ray into that end point, one time in many. A dump of
the thread stacks only (no heap) cannot show what. The spurt fires every few seconds in a big fight, and the freeze
came about once an hour of arena play.

**Removing them should not change the look** [from the engine code, not tested]. 36215 plays its effect only where
the pick ray hits something (`test al, al; je +0xAD1`, the exit, right after the pick call). A ray with no length
almost never hits, so these spurts have almost never shown.

**Aiming them down instead was not chosen** (curator, 2026-11-14). `(0, 0, −1)` would stop the freeze too, but every
spurt would then put blood on the ground under the body: a visual change.

**The 11-06 attribution was wrong.** That freeze's write-up blamed FEC's creature death script, because 512.0 and −1.0
were somewhere on that stack. Here those values are on the stack too, but the native's argument slots say (0, 0, 0)
and `false, true`, which is not FEC.

## Verification

`tools/01` asserts each of these, or stops:

- the DF patch's shipped source rebuilds to its shipped `.pex`: the same 214 strings and the same 54
  `PlayImpactEffect` calls;
- exactly 12 zero-direction calls are matched and commented out, and no zero-direction call is left outside a comment;
- the fork declares the original 44 properties, so it is safe on existing saves;
- the fork keeps every shipped string and has 54 − 12 = 42 `PlayImpactEffect` calls.

It compiles with `Dismembering Framework/source/scripts` on the import path (`DismemberingFramework.IsDismembered`).

## Not covered

- **Deflection's `FL_VFXScript`** passes the same zero direction (length 1) on its hit VFX. It is not in the dump, so
  it is left alone. If a freeze dump ever shows length 1.0 in the native's slots, fork it the same way.
- **The engine's grid walk itself.** It has no iteration cap, so any other zero-length or absurd ray can still freeze.
  A native cap would need a DLL; not built (the curator prefers fewer shipped DLLs).
